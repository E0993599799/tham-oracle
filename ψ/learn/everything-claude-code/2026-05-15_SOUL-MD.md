## What is SOUL.md?

SOUL.md defines the core identity, principles, and orchestration philosophy of Everything Claude Code (ECC)—a production-grade AI coding framework built on agent specialization and automated workflows. It's the constitutional document that explains why ECC works the way it does: route early to specialists, test-driven, security-first, immutable state, and plan-before-execute. ECC ships with 30 specialized agents, 135 skills, 60 commands, and hook automation for modern software development.

## Key Concepts & Principles

- **Agent-First Routing** — Specialists (planners, reviewers, security auditors, build resolvers) are invoked early, not as afterthoughts
- **Test-Driven Development** — Refresh tests before trusting implementation changes; tests are first-class proofs
- **Security-First** — Input validation, secret protection, safe defaults baked into every agent and skill
- **Immutability** — Explicit state transitions preferred over mutation; easier to reason about, safer to reverse
- **Plan-Before-Execute** — Complex changes broken into deliberate phases with clear contracts

## Notable Patterns & Frameworks

1. **Agent Orchestration** — Specialists proactively invoked, not manually routed
2. **Hook Automation** — Automated workflows trigger at key lifecycle points (pre/post commit, test, deploy)
3. **Cross-Harness Portability** — Identity, governance, and skill catalog shared across multiple harnesses (initial portability layer)
4. **Skill Atomicity** — 135 skills each have a single clear responsibility

## Relationship to Claude Code Workflows

- ECC is a **production reference** for how Claude Code should behave: specialized agents, governed skill use, automated safety gates
- The **agent-first** principle aligns with Claude Code's design to route tasks to the right specialist tool/agent early
- **Hook automation** mirrors Claude Code's capability to execute workflows at key points (git lifecycle, deployment, etc.)
- Fits naturally into Oracle/Forge orchestration: ECC's skills and agents can be composed as lane-specific workers

## Actionable Insights for Oracle/Forge Systems

1. **Adopt Agent Specialization** — Forge lanes (manual, Core/GitHub inbox, Codex, Hermes) should have specialists for common failure patterns
2. **Test-as-Proof** — Every automated task should leave behind test evidence or probe results, not just exit codes
3. **Immutable Audit Trail** — State transitions (queued → running → completed) should be logged, never mutated
4. **Early Routing Contracts** — Design lane-selection logic upfront; don't route tasks reactively when they fail
5. **Hook-Driven Safety** — Integrate memory gates, intent decode, and risk gates as pre-execution hooks, not manual checks
