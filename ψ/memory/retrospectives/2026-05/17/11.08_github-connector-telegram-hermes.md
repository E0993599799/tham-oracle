## Architecture Decisions

### GitHub Connector Design

Chose **mailbox-v1 schema** (compatible with obsync) over ad-hoc formats:
- Reason: ธาม already familiar with obsync; reduces cognitive load for future connectors
- Trade-off: Requires JSON structure vs. plain text; benefit = machine-readable + extensible
- Safety: Allowlist-only shell commands, `foreground_allowed: false` enforced, 30s timeout

### Workflow vs. Local Poller

Split responsibility:
- **Workflow** (GitHub Actions): parses JSON, runs allowed shell, commits output (cloud isolation)
- **Poller** (WSL script): detects new files in `ψ/inbox/github/`, prints to stdout (real-time feedback)
- Reason: GitHub Actions is stateless + isolated; WSL poller integrates with tham's existing Telegram pattern
- Result: Same real-time experience as Telegram, same safety boundaries

### Output Format: Same as Telegram

Chose `ψ/inbox/github/YYYYMMDD_HHMMSS_github.txt` (matching `*_telegram.txt` pattern):
- Reason: tham already has monitor scripts for this format; minimal code reuse
- Could have: created separate handler, but that's premature abstraction
- Benefit: Telegram + GitHub inbox converge on same tham processing layer

### `/oasync` Command

Designed `scripts/oasync-push.sh` to route via separate `E0993599799/oasync` repo:

## Lessons Learned

1. **Assume verification before design** — When routing through an external repo (oasync), verify it exists and is accessible BEFORE building integration. Single `gh repo view` call saves 15 min of design-then-fail. Applies to any external dependency.

2. **Reuse inbox patterns over creating new ones** — Telegram already has a working `*_telegram.txt` → monitor → process pattern. GitHub output should use the same format, not invent `*_github_processed.json` or queue systems. Saves code, reduces bugs, faster understanding.

3. **Allowlist-only shell is cheaper than permission gates** — obsync's approach (hardcoded allowlist: git status, git log, maw ls, cat) is simpler and safer than a permission system. Doesn't scale to 1000 commands, but for small CLI use (tham, bot, dashboard), it's the right choice. Lesson: Check if allowlist fits before overengineering RBAC.

4. **Store raw shell output as text, not JSON** — tempting to output `{"command": "git status", "stdout": "...", "exit_code": 0}` in JSON. Actually, just store `command output as-is` + metadata in filename. Simpler parsing, tham integrates with Telegram monitor without adaptation. Lesson: flatten data structures until you need nesting.

5. **PowerShell script safety: -NoProfile, no popups** — CLAUDE.md enforced: "No foreground CMD/PowerShell popup." This is load-bearing for Windows automation — users hate surprise terminals. Script uses `-NoProfile -ExecutionPolicy Bypass -File` pattern, which is correct. Lesson: Always default to background execution; require explicit opt-in for foreground.
