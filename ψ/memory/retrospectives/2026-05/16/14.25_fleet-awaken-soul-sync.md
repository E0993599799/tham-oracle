## Honest Feedback

**3 friction points ใน session นี้:**

1. **Case sensitivity surprise**: `Omega` vs `omega` ใน ghqFind เป็น silent failure ที่ debug ยาก maw ไม่มี error message บอกว่า "found Omega but searched omega" — แค่ไม่เจอ ต้องไปอ่าน source เอง ถ้า maw มี `--verbose` flag ที่บอก path ที่ search จะดีมาก

2. **Fleet config iteration loops**: ธามต้อง iterate fleet configs หลายรอบ — ครั้งแรกใส่ `project_repos`, scan ไม่ detect, ลบออก, สร้าง repos จริง, scan อีกรอบ process นี้ใช้เวลานานกว่าที่ควร เพราะไม่ได้อ่าน scan source code ก่อน

3. **`maw oracle scan --all` ดูดข้อมูลเกินที่ต้องการ**: การ sync ด้วย `--all` ทำให้ได้ Soul-Brews-Studio remote oracles เข้ามา 7 ตัวที่ต้องลบออกทีหลัง ถ้ารู้ว่า `--local` เพียงพอก็ควรใช้ตั้งแต่แรก

## Lessons Learned

1. **อ่าน source code ก่อน assume API behavior** — เมื่อ CLI tool ทำงานไม่ตามที่คาด วิธีที่เร็วที่สุดคืออ่าน implementation ไม่ใช่ลอง flag ต่างๆ

2. **Case sensitivity ใน filesystem detection เป็น silent failure** — ควร test เสมอด้วย `ghq list | grep -i <name>` ก่อน assume ว่า repo ถูก detect แล้ว

3. **`--local` vs `--all` สำคัญใน registry sync** — ใช้ `--local` เมื่อต้องการเฉพาะ local repos เท่านั้น `--all` จะดูด remote oracles จาก org อื่นเข้ามาด้วย

4. **Dedicated repos ต่อ agent เป็น requirement ของ maw** — agents ที่ share repo จะ detect ได้แค่ 1 entry ต่อ repo, ไม่ใช่หลาย entries
