## Honest Feedback

**3 friction points this session:**

1. **Rebuild-while-running destroyed 30+ minutes.** I killed the server AFTER starting the rebuild. In retrospect this is completely obvious — you can't rewrite files a running process is reading. But I had the mental model "the server only loads compiled routes on request, not at startup" which was partially wrong. The real issue was that Next.js writes intermediate files during build that the server might try to read. The protocol must be: kill → build → start. No exceptions. This cost significant time and token spend.

2. **Multiple stale curl loops from background tasks flooded the server.** Previous background commands (`until curl ... do sleep 2; done`) were still running from earlier in the session. When I started a new server, these immediately hammered it with requests, creating a flood of CLOSE_WAIT connections that made the new server appear broken. These loops should have been cleaned up when previous background tasks completed. Background task hygiene matters.

3. **Token overhead from repeated rebuilds.** Each `bun run build` takes ~60s and produces output that fills the context. Over 4 builds this session, that's 4+ minutes of build time plus all the stdout captured in context. A smarter approach would be to keep the server in dev mode during debugging, switch to production mode only for final verification.

---

## Lessons Learned

1. **Kill the server before rebuilding compiled output.** Rebuilding Next.js `.next/` while `next start` is running corrupts compiled chunks, causing the server to accept TCP connections but never respond to HTTP requests. Rule: always `pkill -9 next-server` before `bun run build`.

2. **Background loops from previous bash tasks accumulate.** `until curl ... do sleep 2; done` loops from earlier commands continue running across the session. They will hammer any new server started on the same port. Kill old loops before starting fresh server: `pkill -f "curl.*3005"`.

3. **Shell paths with spaces in template literals must be double-quoted.** When constructing shell command strings in TypeScript template literals with `${REPO_ROOT}`, if REPO_ROOT contains spaces, the shell will split at whitespace. Always wrap: `` `bash "${REPO_ROOT}/script.sh"` ``.

4. **Promise.race is a correct pattern for hard-limiting route handler execution time in Next.js production.** The AbortController timeout alone is insufficient when some fetch calls may not honor abort signals quickly. A 7s global `Promise.race([handler(), timeoutPromise])` guarantees the route always returns.
